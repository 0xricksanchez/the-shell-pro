# Domain docs

This repository uses a single-context domain-documentation layout.

## Before exploring

- Read `CONTEXT.md` at the repository root when it exists.
- Read relevant decisions under `docs/adr/` when they exist.
- If either location is absent, proceed without creating placeholder documentation.

## Vocabulary

Use the terminology defined in `CONTEXT.md` in issue titles, tests, implementation notes, and architectural proposals. If a required concept is missing, note the gap rather than silently introducing conflicting vocabulary.

## Architectural decisions

Surface any conflict with an existing ADR explicitly instead of silently overriding it.
